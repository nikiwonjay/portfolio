UNDERSTAND

USER CONTROL

核对后逐项填写

只接受资料库中存在的候选 ID，校验返回格式。目标变化时清除旧结果，覆盖已有内容前询问确认。

使用：在设置中配置自己的 OpenAI Compatible API 地址、Model 和 API Key，启用 AI 字段识别并保存授权。连接招聘页，点击输入框，再点击 AI 识别按钮。AI 默认关闭，供应商可能收费。

字段识别发送网页标签、分组、格式、选项及候选字段名称，不发送资料字段值或完整资料库；自定义标题可能包含个人信息，发送前请留意。翻译与简历 AI 为独立可选功能，会发送用户选择的相关文本。146 项测试通过，AI 测试使用模拟服务，未验证真实供应商调用；模型判断仍需核对。下方耗时估算不包含 AI 请求等待时间。

PROBLEM → SOLUTION

把时间花在申请上，减少重复搬运资料。

一份网申往往重复询问学校、专业、实习职责和起止日期。传统方式需要切换简历，找到对应经历，选中复制，再回到网页粘贴。JobPilot 将资料集中在侧边栏，用字段关键词和上下文推荐候选；遇到多段经历时，指定记录，避免把不同经历混在一起。

  • 一次整理，重复使用：导入简历并维护结构化记录，跨网站搜索或匹配同一份资料。
  • 日期与选项少点几次：在兼容的控件中，将日期文本转换为日历年月日选择，并辅助选择下拉项；填写后仍需检查。
  • 按需处理中英文：点击翻译按钮，将分组和资料翻译到英文对应字段。依赖浏览器翻译能力或用户配置的 AI 服务，专有名称与译文仍需核对。

ENGINEERING TRADEOFF

为什么保留逐项选择，而不是全自动？

难点不是把文字写进去，而是确定“这条资料应该填到哪一段经历”，并确认网页确实接受了操作。全自动可针对特定网站开发，但通用插件需要处理更多不确定性。

  • 同名字段与不同叫法：“结束时间”“毕业日期”可能指同一字段，也可能属于实习。需要结合分组、标签和经历上下文；仅命中几个字不足以判断归属。
  • 重复经历与新增按钮：一个空白教育区域可能对应本科或硕士。添加后网页会异步重绘，顺序、必填项和可添加次数也不同，容易填错记录或重复添加。
  • 动态日期与下拉：原生下拉、自定义菜单、年月日历和年月日历结构不同；还要处理灰色相邻月份、禁用选项、事件触发及受控组件回写。
  • 权限与验证：跨域 iframe、网站访问权限和页面变化影响定位。DOM 中出现文字不代表网站已保存，需要核对控件显示值和状态。

当前取舍：自动推荐资料，辅助单字段填写与兼容控件选择；由用户确认经历归属。未识别时提供搜索和复制，不整页批量填写、不自动新增经历、不提交申请。

实现重点：动态网页交互

基于 Manifest V3，将侧边栏、后台通信和内容脚本分开。通过 DOM 与 MutationObserver 识别字段和动态控件，再将用户选定的资料写入当前目标。

设计取舍：用户控制与本地优先

采用逐项填写流程，不自动提交申请或批量新增经历。资料保存在 chrome.storage.local；本地解析无需 API Key，云端 AI 仅使用用户配置的服务。

保存保护：自定义分组草稿保留，统一保存入口；并发保存检测冲突，避免旧页面覆盖新资料。
识别改进：优先读取字段标签，减少把“请输入”当作项目名称等字段的情况。
覆盖填写：空白字段直接填写；已有内容时展示原值和新值，确认后替换，并检查目标是否发生变化。
